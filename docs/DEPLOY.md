# Deploying to Vercel

Dunia Pintar 3D is a SvelteKit app built with `@sveltejs/adapter-vercel`. This
file records what deploy actually requires and what was verified — not what is
hoped for.

## What is already in place

| Piece | Where |
| --- | --- |
| Vercel adapter, Node 22 runtime | `vite.config.ts` → `adapter({ runtime: 'nodejs22.x' })` |
| Build output | `.vercel/output/` (Build Output API v3) |
| `.vercel` ignored by git | `.gitignore` |
| Node version floor | `package.json` → `"engines": { "node": ">=20.19" }` |

There is **no `svelte.config.js`** in this repository; the adapter is
configured inside `vite.config.ts`. Do not add a second config file for it.

## Deploy

```bash
npm i -g vercel        # once
vercel                 # preview deployment
vercel --prod          # production
```

Or connect the Git repository in the Vercel dashboard. The defaults are
correct: framework preset **SvelteKit**, build command `npm run build`, output
handled by the adapter. No environment variables are required — there is no
backend, no database server, and no API key.

## What the visitor's browser needs

This app has no server-side data at all. Everything below happens on the
device, and a deploy is not "done" until each of these is true on the target
device:

- **WebGL 2.** Without it the canvas fails and the game shows an error instead
  of a blank screen (`SceneManager` handles the failure explicitly).
- **IndexedDB.** Progress is stored locally via Dexie. In private browsing it
  may be unavailable; the app then plays normally but forgets between sessions,
  and `/parent` says so.
- **`speechSynthesis` with an Indonesian voice.** Narration is not recorded.
  If no `id-ID` voice exists the device default is used, which may mispronounce
  Indonesian. `/parent` discloses this.
- **A user gesture before sound.** Browsers block audio until the first tap;
  the first tap also unlocks narration.

## Verified

Checked against a real production build, not dev mode:

```bash
npm run build
npm run preview -- --port 5299
KIDS_URL=http://localhost:5299 node scripts/kids-smoke.mjs
```

Result: `ALL PASSED` — 133 checks, 0 failures. Server-side rendering returns
`200` for `/` and `/parent`, `404` for an unknown path, and both pages contain
their expected heading in the initial HTML.

## Things that bite in production

- **`.vercel` is git-ignored** and is a local artefact. Never commit it; it is
  regenerated by the build.
- **`static/models/` ships empty.** `AssetManager` probes for
  `/models/Bubu.glb` and falls back to the procedural rig, remembering the 404
  in `sessionStorage` so it is requested once per browser session rather than
  on every load. This is expected, not a deploy failure. Do not deploy a model
  until `CharacterController` has an integration tested against that asset's
  rig, clips, scale and accessory anchors; the current engine only probes it.
- **Speech synthesis is per-device.** A demo on a laptop with an Indonesian
  voice proves nothing about a tablet without one.
- **Immutable asset caching.** `/_app/immutable/*` is served with
  `max-age=31536000, immutable` and a `no-store` 404 for misses. Bricking a
  returning visitor is therefore impossible: a stale chunk gets a 404 rather
  than the wrong file.
- **Portrait phones get a hint, not a wall.** Rotation is never forced;
  forcing it is unreliable on iOS and the game stays fully playable.
